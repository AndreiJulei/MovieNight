# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these files do not exist, proceed silently. The domain-modeling
skill creates them lazily as terms and decisions are resolved.

## Layout

Single-context: one root `GLOSSARY.md` and root `docs/adr/`.
Number ADR filenames sequentially: `0001-<decision>.md`.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
When a needed concept is missing, reconsider the terminology or
note the gap for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, identifying the
decision and explaining why it should be reconsidered.
